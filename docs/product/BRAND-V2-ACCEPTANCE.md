## 2. 跨畫面一致性（#69 第 2 點）

一個測試咬住七頁：`apps/web/test/design-brand-integration.test.tsx`。逐頁打開，問同一組問題 ——

| 問什麼 | 選擇器 | 七頁結果 |
| --- | --- | --- |
| 表身在不在 | `[data-brand-page-body]` | 七頁都有（自定義頁共用 `custom`） |
| 版本抽屜 | `[data-brand-page-versions]` | 七頁都有 |
| Needs 欄 | `[data-gap-rail]` | 七頁都有（含空狀態與載入狀態） |
| 檢查摘要 | `[data-brand-check]` | 七頁都有（loading 也是狀態） |

側欄頁清單與「缺」標記由同一份資料派生（`page.current === null`），所以不會出現「左側欄標缺、頁面卻說有版本」。分組次序固定為 主頁／識別／品牌專屬／應用，空組不畫。

## 3. 兩個內容不同的品牌：差異可數

`packages/contracts/test/brand-two-brands.test.ts`：同一條輸出管線，兩個品牌（Moonic／張記）走一次。

1. **主色與底色不同**：`#0057FF` 對 `#8B1E1E`，tokens 的 `color.brand.primary` 逐字不同。
2. **字體家族不同**：`Noto Serif TC`／`Inter` 對 `Source Han Serif`／`IBM Plex Sans`，prompt 的字體段落不同。
3. **版面次序不同**：同一個 block 詞彙，一個是 `1. swatches → 2. quotes`，另一個反過來 —— 這是主頁的判斷，不是模板。
4. **語氣樣本不同**：各自的句子只出現在自己的 prompt，交叉檢查為零。
5. **HTML 的立場句與色值不同**：renderer 原始碼沒有色值，畫面上的色只能由 payload 來。

第六項：兩個品牌的組成頁一樣多（四頁），所以上面的差異不是「一邊多了一頁」。

## 5. 響應式（#69 第 3 點）

Frame v1.5 §2.9 的三種闊度（1440／1024／768）套用在品牌頁：

- **1024（筆電，側欄 200px）**：範例卡三欄→兩欄；主頁版面那一行拆成兩行（來源與理由各佔一行）；引用清單由「名＋來源同一行」改成兩行。
- **768（平板，側欄 180px）**：兩格並排（襯線／無襯線、名／解釋）疊成一欄；圖像六格一欄；範例卡與載體示範一欄。
- **沒有用 `overflow: hidden` 遮問題**：全部靠 grid 由 3→2→1 與 `flex-wrap`，內容只會換行，不會被切。

**未做**：真機 1440／1024／768 目視截圖。這需要起平台（Postgres ＋ Fastify）＋前端 dev server ＋種一份示範資料；斷點已對齊規格，但截圖對照未做，所以上面第 1 節有兩項標「未對照」。
