# 素材（Material）模組規劃稿

狀態：規劃稿，**未開工**。2026-11-12 記錄。品牌模組 v2 完成後再續。本文件不是施工授權；每張 issue 仍要獨立實作。

## 1. 定位與邊界
素材模組是 Design app 的第三個分頁（品牌、知識、素材、創作）。它對應概念文件四個庫中的 Material（相、片、聲）。價值不在存放，在於「解拆得夠細，讓 agent 在 Create 時找得到、驗得準」。

| 東西 | 住哪 | 規則 |
|---|---|---|
| 標誌、色彩、字體 | 品牌模組 | 不進素材庫 |
| 原料（相、片、聲） | 素材模組 | 只存原料，來源可追溯 |
| 成品（render 出來） | 創作模組的 Create | 不回流素材庫（概念文件原則 4） |
| 品牌圖像頁、已核准範例 | 品牌模組 | 只引用素材 id，不存副本 |

Company-OS 不是中央 DAM：素材屬於部門 app，沒有跨部門的中央素材庫。

## 2. 已定決定（2026-11-12）
1. **主要上載路徑是人在 app 上載**，再由 AI 解析備用；agent 上載只是次要路徑。
2. **三種能力、兩個地方：**
   - 看（VLM）：相片解析，在同一網絡的 Windows GPU 機（NVIDIA）。
   - 聽（語音轉文字，如 Whisper 類）：聲音解析，同樣在 GPU 機。VLM 聽不到聲音，必須另用語音模型。
   - 影片解析：由網上 VLM 負責（支援分段與時間點）。
   - 畫（圖像生成，擴散模型如 ComfyUI＋SDXL／FLUX）：參考圖與替代素材生成，在 GPU 機。這不是 VLM，要分開。
3. **GPU 互損用佇列模式**（見第 4 節）。原話「quote mode」按「佇列模式」理解，待確認。
4. **解析以品牌脈絡為基礎**，分客觀事實層與品牌視角層（見第 5 節）。
5. **入庫欄位由 AI 在解析時填**，員工不填。
6. **解析結果為結構化資料**，不是一段描述。
7. **找料：換說法重搜一次，兩輪後沒有合用的就開素材 Needs**（為了速度）。
8. **生成圖由使用者選**：可當參考圖，也可當替代素材。
9. 素材、傳同的 Needs 間的缺口，沿用品牌模組的「缺口＝ Need」規則。

## 3. 待確認（開工前要答）
1. 「quote mode」是否就是佇列模式。
2. 員工在 app 上載的素材，預設權利是否「公司自家擁有」，並由 AI 風險訊號覆蓋（建議是）。預設值由老闆在策略「素材」槽設定。

## 4. 解析流程與 GPU 佇列
員工拖放上載（可多檔）→ 平台按類型與策略路由 → 解析任務進入佇列 → 結果寫成結構化資料。

**佇列規則：**
- Windows GPU 機一次只服務一件工作。
- 優先次序：使用者按「Generate」與 agent 即時看圖覆核 > 新上載的解析 > 批次重新解析。
- 按模型分組：同一模型的工作盡量連續執行，減少載入模型的等待。
- 狀態可見：排隊中、解析中、完成、失敗。GPU 機離線時工作暫停等待，不自動改走雲端。
- Boss Portal 顯示 GPU 機在線狀態與佇列長度。
- 平台只呈現「提供者」的 HTTP client（和 Hyperframes 一樣只換 base URL），模型不跑在平台裡，不違反「Company-OS 不包 agent」。
- Windows 上部署通常需要 WSL2；看、聽、畫三類服務互相爭用 VRAM，所以必須佇列。

**私隱：** 影片會送到雲端。素材可標「敏感」，標了就只走本地（抽幀加本地看圖，品質較低）。哪些類型預設敏感，由老闆在策略決定。

## 5. 以品牌脈絡解析（兩層）
1. **客觀事實層（與品牌無關，只做一次）：**
   - 相片：描述、標籤、主體、場景、方向、尺寸。
   - 聲音：逐字稿加時間點、語言、說話者、音樂或環境音類型。
   - 影片：分段（起止時間、內容、場景、對白）、整體故事摘要、關鍵幀縮圖。
2. **品牌視角層（每個品牌一份）：** 讀該品牌的平台（立場、受眾、關鍵詞）、圖像頁（像與不像的方向）、色彩角色與語氣，判斷：貼合圖像方向的程度與理由、主色對應哪些色彩角色、適合的用途與渠道、是否偏離品牌。
3. 品牌視角層記住解析時用的品牌版本。品牌改版後只提示建議重新解析，不自動重寫，只重跑第二層。
4. 一個素材可屬於多個品牌，每個品牌各有一份視角結果。

## 6. 入庫欄位由 AI 填，權利要留意
- 來源、描述、標籤、技術資料由 AI 填。
- 來源已知時自動填：經 Needs 上載視為自家製作；員工在 app 上載的預設值由老闆在策略設定（建議「公司自家擁有」）。
- AI 看得出浮水印、第三方標誌、可辨認的臉孔、背景音樂，卻不知道授權合約。發現風險訊號就改成「需確認」，並自動產生缺口（例：「畫面中有可辨認的人物，缺胖像授權」）。
- 需確認的素材仍可使用，但 agent 搜尋時標示原因，草稿可用，對外出街前要補。
- 不設審批閘。權利欄位包括權利人、授權類型、可用渠道、地區、到期日、授權文件；到期前提醒。

## 7. 找料辴圈
1. agent 用自然語言加篩選條件搜尋，取前幾名。
2. agent 用 vision 實際看候選圖（影片看關鍵幀），判斷是否真的合用。
3. 不合用就換說法重搜一次。
4. 兩輪後仍無合用的，開素材 Needs。
5. 每次判斷留紀錄：搜了什麼、看了哪些、結論與理由，用於日後檢查 agent 為什麼選錯。
6. 排除規則：過期或權利不明的素材預設標示原因，不悄悄用。

## 8. 素材 Needs（Needs 的一個子型，附拍攝說明）
- **相片：** 文字說明（主體、構圖、光線、尺寸比例）。「Generate」用 GPU 機生成幾張圖。
- **影片：** 逐鏡拍攝腳本，每鏡有時間點、場景、動作、對白、鏡頭、聲音；整體故事說明；每鏡生成參考幀。
- **生成圖的兩個選擇（使用者決定）：**
  - 用作參考圖：掛在這張 Need 上給拍攝的人看，不進素材庫。
  - 作為素材使用：標記為 AI 生成且永久顯示，記錄工具與 prompt，進入素材庫並填回 placeholder，Need 標為已吸收且註明由生成解決。
  - 老闆可在策略加限制（例如真人肖像或產品實物不接受 AI 替代），預設不設限、只標示。
- **上載回來：** 員工把拍好的檔案上載到這張 Need，系統解析並和拍攝說明比對（例如「第 2 鏡缺少對白」），不符合走既有的「需要補件」狀態。確認後入庫，同時填回 project。

## 9. 策略槽「素材」（Boss Portal，只有老闆可改）
- 分類與受控詞彙。
- 各類型的解析指引（客觀層與品牌視角層的提示）。
- 路由與私隱政策（哪些類型走本地、哪些可以上雲，哪些預設敏感）。
- 員工上載的預設權利。
- 拍攝說明模板與生成限制。
- 生成的參考圖必須遵守品牌圖像頁的方向。
- GPU 機位址與雲端金鑰屬設定，只有老闆可改，金鑰不顯示。

## 10. 資料模型（草案）
素材（kind、file_ref、source、provenance）、客觀事實、品牌視角（每品牌一份，記品牌版本）、素材分段（影片與聲音的時間範圍）、權利、解析任務、找料判斷紀錄、拍攝說明、參考幀、使用紀錄（釘住版本）。內容一律是帶型別的 payload，沿用品牌模組的「單一真相」與 tokens／prompt 映射原則。

## 11. 暫定 issue 清單
1. 總綱與決定條目（素材模組頁清單）。
2. 策略「素材」槽。
3. 資料模型與儲存。
4. 解析佇列與提供者（看、聽、畫、雲端影片）。
5. GPU 機健康狀態與設定。
6. 人手上載介面。
7. 解析結果資料（客觀層與品牌視角層）。
8. 權利與到期。
9. 找料辴圈與判斷紀錄（人用的搜尋與 agent 用的 MCP 讀取工具）。
10. 素材庫與詳情頁。
11. 集合與封存。
12. 素材 Needs（拍攝說明、參考圖生成、上載比對）。
13. 與品牌圖像頁、創作的引用與版本釘住。
14. AI 生成素材的來源追溯。
做法和品牌模組一樣：先寫完整設計稿（規格加高保真圖），再出 issue 全文與 Workbuddy prompt。

## 12. 與現有文件的衝突與注意
- 概念文件寫明「不上載後等人覆核標籤」。本規劃保留標籤不覆核，但權利不同：用「缺口加標示」而不是審批閘。
- 概念文件原則 4「成品留在出身的 app」保留；生成的替代素材是原料，不是成品。
- 品牌模組的圖像頁與已核准範例只能引用素材 id。
- Needs 的第三個子型（附拍攝說明的素材）要在 DECISIONS.md 新增條目。
- Frame 的硬規則（無搜尋、無深色、Needs 住外殼、藍色只用於寫入或確認）照舊適用；「搜尋」指的是全站搜尋框，素材庫內的篩選與找料是模組功能，要在開工前確認是否相容 C63。
