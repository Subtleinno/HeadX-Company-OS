# Stage 04E · UI／UX 與空間體驗（v1）

- edit.html   編輯（10 張卡片、完成度、前階段匯入、貼回 AI 結果、匯入匯出）。含：元件實驗室（依你的色值與 4B tokens 預覽並逐狀態檢查顏色對比）、無障礙測試計畫預覽、可編輯的客戶旅程與服務藍圖（含情緒曲線）、客流容量計算（Little's law）、與建築署《設計手冊：暢通無阻的通道》公開數值對照
- view.html   展示頁
- agent.html  AI Agent 合約：ui-space-system-prompt.txt、stage4e-brief.json、ui-tokens.css、component-spec.json、a11y-test-plan.md、journey-blueprint.csv、space-spec.json、ui-prompt.txt、space-prompt.txt、ui-space-guide.md

用法：用瀏覽器打開 edit.html。資料存在瀏覽器 localStorage；換瀏覽器請用「匯出／匯入 JSON」。
前階段：若 localStorage 已有 brand_brief_stage0／1／2／3／4a／4b／4c／4d 會自動讀取；也可在側欄手動匯入各階段 brief JSON。匯入 4A 時，若色值空白，會自動帶入 4A 的 5 個色值；匯入 4B 時，會使用其 surface_tokens（圓角、陰影、邊框、焦點外框）與深色色彩變體。

重要限制
- 對比檢查只涵蓋顏色，使用 WCAG 2.2 的數值（文字 4.5:1、大字與元件 3:1、焦點 3:1、目標至少 24×24 CSS px）作設計門檻。鍵盤操作、焦點行為、螢幕閱讀器、重排與真人測試必須由人類執行；原型不能宣稱「已符合 WCAG」。SC 編號請對照 W3C 原文。
- 禁用元件對比豁免，但仍須可辨識並說明原因；語意色未填時使用參考預設值並標示須確認。
- 暗黑模式（隱藏取消、預選加購、羞辱式拒絕文案、假倒數等）列為禁區；個人與健康資料須最少化收集並取得適當同意（香港適用《個人資料（私隱）條例》；具體合規須由專業人士確認，不是法律意見）。
- 空間：建築、消防、電氣、衛生、無障礙與規管要求須由註冊專業人士確認。建築署手冊數值（門淨寬不少於 800mm、建議 850mm；通道淨寬不應少於 1200mm；1500mm 可讓兩部輪椅對向通過；1500×1500mm 迴轉空間）為公開摘錄，以最新版為準，不是法律意見。色溫分類（約 3000K 以下偏暖、3500–4100K 中性、5000K 以上偏冷）是一般慣例。
- 旅程與服務藍圖內容須來自真實觀察或明確標示為假設，原型不產生研究數據。
- 容量計算只是平均值估算（Little's law），高峰波動須另外預留餘量。
- 沒有風格相符度分數；AI 提案不等於核准；approval.state 固定為 draft。
- 選項內容是通用知識的起始草案，尚未逐項來源查證。
- 4F–4H 不會自動讀取本階段；請匯出 stage4e-brief.json 帶過去。

測試：已用 Chromium（Playwright）開過 edit／view／agent 三頁：點擊選項、匯入 4A 與 4B、元件實驗室逐狀態對比（含深色主題）、編輯旅程表與情緒曲線、容量與手冊對照、貼回 JSON、重新載入保存，均無 console 錯誤；手機寬度（390px）三頁都沒有橫向捲動。未做 Safari／Firefox、螢幕閱讀器、真實使用者測試、實體空間與專業人士審閱，以及用 Stage 1–3 真實 brief 的驗收。
