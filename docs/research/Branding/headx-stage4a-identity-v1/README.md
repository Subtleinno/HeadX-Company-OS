# Stage 04A · 核心品牌識別 v1（HeadX 品牌創意系統）

接在 Stage 0 之後，依《品牌創意系統範圍重整》重新建立：識別任務與架構 → 視覺方向 → Logo 類型與風格（分開）→ 標誌系統 → 字體 → 色彩 → 配色組合 → 輸出需求 → 候選比較 → 核准記錄與下游影響。檔案結構沿用 headx-stage0-business-v2。

- edit.html   編輯（13 張卡片、完成度、一致性與準備度檢查、討論提示詞、貼回 AI 結果、匯入／匯出）
- view.html   展示頁（唯讀；清楚標示草稿）
- agent.html  AI Agent 合約（identity-context.txt、design-agent-prompt.txt、stage4a-brief.json）
- options.js  全部選項（可直接增刪）　core.js 狀態、檢查、就緒清單、輸出、貼回　prompts.js 13 份討論提示詞　ui.js 預覽元件　color.js WCAG 對比　shared.css

## 內容
13 個選項庫、146 個選項；其中 Logo 類型 7、Logo 風格 11、字體個性 11、色彩風格 12，共 41 個選項有完整的資料模型欄位（解釋、視覺特徵、傳達感受、適用、避免、互補、刻意對比、硬性限制、可調參數、Image Prompt 範本）。26 個單選組、114 個選項。

## 重要
- 選項內容是設計慣例的起始簡報，不是已查證的結論；來源、授權、測試與專業驗證欄位預設為空。
- AI 貼回只會把涉及的卡片標為『AI 提案』；不會填入核准者、授權或測試結果，也不會把任何東西設為已核准。
- 『已核准』只是本機記錄（需要核准者、版本、沒有尚缺項目），不是正式審批、權限或發布。已核准項目被修改會自動改為『需修訂』並記錄下游影響。
- 色票對比依 WCAG 2.2 公式計算；不等於真實介面已通過無障礙測試。
- 沒有風格相符度分數。候選比較要求相同內容、相同觸點。
- 不產生真實 Logo、字體檔或印刷檔；字體授權、商標相似度、印刷打樣需人類與專業人士確認。

## 驗證
已用 Node 做：語法檢查、選項 ID 唯一性、檢查規則、完成度、匯出再匯入一致、AI 貼回不得核准的保護、提示詞結構，以及以模擬 DOM 跑三個頁面的初始渲染與主要互動。尚未在真實瀏覽器、手機版與無障礙工具中驗收；尚未整合進 HeadX 正式系統。
