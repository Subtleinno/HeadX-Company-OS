# 08 · 補充：你原文未寫到、但必須處理的部分

版本 v0.1 ｜ 狀態：規劃稿

## 1. 安裝與第一次使用（Onboarding）

- 一部機器一間公司；全部以 Docker 自架；**裝完是空的**。
- 第一次開啟：建立老闆帳戶 → Company Profile（公司名、語言、地區、啟用的 app）→ 品牌入口（已有品牌／建立新品牌）。
- **空白狀態設計**：每個模組的第一個畫面要告訴人「下一步是甚麼」，而不是空表格。
- 提供「示範公司」資料包（可一鍵載入與清除），方便試用與測試。

## 2. 平台殼與權限

- 平台殼只做：切換、身份、註冊、事件。
- 角色：Boss／Staff／AI Agent／External。
- 權限分四層：app／物件／動作／欄位。
- **API／MCP 與介面同一套權限**：agent 以「請求者身份」被授權，不是以資料庫連線。

## 3. 決策狀態與版本（貫穿所有模組）

| 狀態 | 意思 | AI 如何看待 |
|---|---|---|
| 未決定 | 尚未選擇 | 可與人討論選項 |
| AI提案 | AI 寫的草稿 | 可引用，但須標明未確認 |
| 已確認 | 人已確認 | 視為事實 |
| 需修訂 | 上游改了，這項可能失效 | 引用時警告 |

- 每次修改保留修訂記錄，可比較與回滾。
- **下游影響**：改了品牌色，列出受影響的模板、產出與配方（Stage 4A 已有此概念，應提升為平台通用功能）。

## 4. 備份與還原（第一優先）

- Postgres：持續歸檔＋定期完整備份；MinIO：版本化＋異地副本。
- 目標：RPO ≤ 1 小時、RTO ≤ 4 小時；**每季實測還原**。
- 因素材佔空間大：區分「原檔（必備份）」與「代理檔／縮圖（可重生成）」。

## 5. 模型路由與成本

| 任務 | 建議層級 |
|---|---|
| 品牌訪談、策略、文案、疑難判斷 | 強模型 |
| 抽取、標籤、描述、組裝、Lint 修正 | 快速低成本模型 |
| 圖片理解（素材描述） | 具視覺能力的模型；大量批次用低成本版本 |
| Render、檢索、資料庫 | 不用 LLM |

- 路由表放在 config，可更換；每次呼叫記錄 token 與成本，供預算上限與告警。
- **模型表現與價格變化快，上線前以黃金查詢集與抽樣任務實測再定。**

## 6. 私隱、版權與合規（只作提醒，須專業人士確認）

| 項目 | 要點 |
|---|---|
| 個人資料 | 香港《個人資料（私隱）條例》適用性須確認；人臉、車牌、客戶資料標 sensitive |
| 肖像同意 | 素材記錄 consent；公開使用前檢查 |
| 版權／授權 | 圖庫、音樂、字體、AI 生成物各有條款；記錄授權與到期 |
| AI 內容披露 | 不同平台與法域可能要求標示 AI 生成；在產出設定中提供標示欄位 |
| 廣告宣稱 | 醫療、療效、金融等行業有特別規定；一律 decision Needs＋`kb.check_claims` |
| 資料離境 | 呼叫外部模型 API 時，哪些資料可以送出，需訂定規則（尤其客戶資料） |

## 7. 語言與在地化

- 內容語言：繁體中文（香港書面）、粵語口語、英文。
- 同一素材與知識可多語欄位；模板 slot 支援不同語言長度。
- 字體：須有中文（繁）字體與授權記錄。

## 8. 字體與資產授權登記

```text
font_license: 名稱、來源、授權類型、可否內嵌／商用／轉換、到期、購買證明檔
```
PPT B 級輸出與網頁內嵌字體前須檢查。

## 9. 外部發佈（之後）

- 目前以「複製、手動貼上」為主。
- 之後才評估：IG／FB 排程發佈（需平台 API 授權與審核）、WordPress REST、電郵平台。
- 發佈動作屬不可逆，預設為 decision Needs。

## 10. 可觀察性與除錯

- 每個 Project 保存 `route_log`、Render log、Lint、Provenance，人可「回看為何出現這個結果」。
- 儀表：產出量、Needs 開立／完成、素材重用率、每產出 token 成本、失敗率。

## 11. 測試與驗證（對應開發憲章）

| 層級 | 內容 |
|---|---|
| L0 | 型別、schema、lint |
| L1 | Registry 契約（projects／needs／approvals／schedule）＋架構邊界 |
| L2 | 不變量：Needs 狀態不可跳、素材授權不可繞過、Spec 白名單 |
| L3 | migration 往返 |
| L4 | docker compose 起來後走完整條 IG carousel |
| 黃金集 | 素材檢索 30–50 條查詢；模板在多品牌 Lint；claims 檢查樣本 |

## 12. 範圍守則（避免做太大）

- 第一版只做 Native 與 PPT（見 01）；不做排程發佈、不做影片自動剪輯的複雜功能。
- 一次只驗證一條完整閉環：**IG carousel（香港主題、真人相片、已驗證知識、品牌模板）**。
- Framework Engine 在閉環驗證後才開放給 AI 啟用。

## 13. ERP（之後決定）

- ERPNext／ERPClaw 只接給真正需要的部門（Sales、Operations、Finance）。
- Marketing 不直接接 ERP，需要的資料經 MCP 向該部門索取（唯讀）。
