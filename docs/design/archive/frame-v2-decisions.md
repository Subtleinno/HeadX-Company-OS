## 一、八項決定

### D-01 Needs 進外殼（新）

Needs 唔再等 Boss Portal 業務頁，佢屬於外殼。三個位置，各有分工：

| 位置 | 內容 | 點擊 |
|---|---|---|
| 頂欄右側 | `Needs 7`，有逾期時加 `・逾期 1` | 開 Needs 頁 |
| 內容右側欄（新增） | 只列**此頁**相關嘅 Needs，4 條為上限，底部顯示已關閉數量 | 開該筆 Need |
| Needs 頁 | 全部 app 嘅 Needs，可按狀態、來源篩選 | — |

右側欄規則：

- 只喺頁面宣告「可產生 Needs」時出現，寬 320px。
- 視窗窄過 1280px 自動收起（唔用抽屉遮內容）；此時用戶用頂欄計數去 Needs 頁。
- 數量 0 時仍然保留欄位，只顯示一句說明，避免版面跳動。
- 排序：逾期 → 待認領 → 待你決定 → 進行中 → 待吸收。已關閉唔列入。

排序理由：Need 嘅價值係「唔好漏」，所以先排會爛掉嘅。

### D-02 權限不足頁（08）修正

非管理級人員唔應該見到 Boss Portal 嘅任何結構。舊圖仍然顯示 app 名同第二層分頁，等於把骨架漏出去。

決定：權限不足係一個**獨立全屏狀態**——冇 app selector、冇第二層分頁、冇左側欄、冇頁尾據點入口。只有一張卡同一個返回。

### D-03 空狀態唔放假按鈕

移除藍色 `+`。空狀態只留一句狀態同一句解釋，唔放任何撳落冇反應嘅元素。要放按鈕，就一定要真係去到某個目的地。

### D-04 全站唔要搜尋

移除頂欄搜尋（⌘K）同頁內「搜尋此頁」。列表要收窄範圍就用篩選（chips / 下拉），唔用文字框。

### D-05 取消黑色主按鈕

用色規則收成一條：

- **藍 `#0057FF`**：唯一嘅主要動作，會寫入或確認（新增據點機器、下載憑證、批准）。
- **描邊**：次要或離開（上一步、返回工作區、取消）。
- **近黑 `#171614`**：只做文字同選中狀態（模組分頁、左側欄選中、app 標記），唔再用嚟做實心按鈕。

### D-06 唔做深色模式

撤銷 C49。UI 只做淺色。`design-tokens` 唔需要深色組，`#159` 之後亦唔使再補。

### D-07 四層導覽保留（更正我上一輪嘅意見）

結構係三層控件加一個路徑，各有各做：

1. **第一層** app selector：揀 app。
2. **第一層右** 品牌 selector：揀品牌（品牌型 app 才需要）。
3. **第二層** 模組分頁：品牌 / 知識 / 素材 / 創作——呢啲係 **app 嘅模組**。
4. **左側欄**：該模組下面嘅**頁面**。
5. **麵包屑**：只負責講「你而家喺邊」，冇導覽功能。

所以麵包屑唔係重複，係定位。保留四段。唯一調整：768px 時模組分頁收成「模組・品牌 ▾」，唔可以冇咗個入口。

### D-08 文案統一繁體中文（香港書面語）

規則：

- 書面語，唔用「呢 / 喺 / 嘅 / 唔 / 嗰」。口語只留喺對話，唔入 UI。
- 稱呼用戶用「你」，唔用「閣下 / 您」。
- 按鈕用動詞開頭，2–6 字。「新增據點機器」而唔係「據點機器新增」。
- 狀態用短語，唔加句號。「待認領」「已上載・待吸收」。
- 中英並列：中文在前，一個空格，英文在後。「銷售 Sales」。
- 日期一律 `YYYY-MM-DD`；時間 `HH:MM`。數目用阿拉伯數字。
- 唔用感嘆號、唔用 emoji、唔用「請注意」。
